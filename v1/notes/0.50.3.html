doz 0.50.3

A secret Dozable holds for a session: --secret (issue #420; step 6 of the session access program, #405). A token a session needs for a service on your Mac or your Tailscale network no longer has to be a real value inside the session.

  • --secret VAR,src=PATH,to=HOST:PORT[,header=NAME][,file=FILEVAR] (repeatable, up to 4) on doz create, doz run NAME and doz run @mac (fenced). The value is read from the file and kept by Dozable; the session gets a placeholder in VAR and, with file=, a file holding the same placeholder with its path in FILEVAR. The proxy swaps the placeholder for the value only on requests to that exact host and port (default header: Authorization: Bearer).
  • The source file must be yours alone (no group or other access), a regular file, at most 1800 bytes of printable text, and outside anything the session can read. The value is never taken from -e or the command line; -e VAR=… for a secret's variable is refused.
  • It does not widen reach: the destination must already be open (--host-port PORT for host.dozable.internal:PORT, or a site:HOST:PORT permission).
  • Over plain HTTP a secret travels only to this Mac's ports (host.dozable.internal) or a Tailscale address (100.64.0.0/10, every address the name resolves to, and only while this Mac is itself on a Tailscale network). Setting network.placeholders_plain_http (on by default) turns that off. Every other placeholder is still never sent over plain HTTP.
  • Kept across a daemon restart in a keychain item of its own (when the login keychain is locked: in memory only, and the launch says so). Removed when a sandbox is shut down, reset, renamed or removed, and when a fenced session's record goes. A duplicate never copies a secret.
  • Shown on the launch line and in doz net show (--json secrets) by variable, destination and a 12-character fingerprint — never the value.
  • Limits to know: a placeholder (never the secret) sent inside an encrypted tunnel to another site passes unseen, as every placeholder does; "this Mac is on Tailscale" cannot tell Tailscale from a carrier network when both are present; doz run @mac --dry-run does not list secrets yet.
  • Tests: make test 1762 / 0; make test-cli-fence passes with the new rows (the value absent from the store, the log and the session; swapped on the route, refused on another port, the alias and another site; the setting off; a Tailscale address through the test seam; the refusals; the record across a daemon stop). make test-cli-host is the implementing agent's run. No VM test: sandboxes rely on the shared proxy code and the unit tests.
