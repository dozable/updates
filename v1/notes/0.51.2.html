Chat, steps 3–5: reactions and delivery by webhook (hidden) (issue #440; chat loop 698). Still behind the hidden command; nothing here is visible to a user.

  • Reactions by all three paths (a reaction line, /react, the page's call), each done once per id; the same reaction again takes it off; each is an event on the live stream.
  • Delivery to a bot's webhook: each message to each bot is its own call, tried at 0, 5 and 20 seconds with a 30-second limit; the delivery states the page shows; edit and delete notices; a held message released in order; at start, what was never handed over (up to a day old) is delivered again, once.
  • The webhook client is deliberately narrow: it calls only the address the config names, follows no redirect, uses no proxy from the environment, keeps no cookies or cache, and never reads the answer's body. A slow or dead webhook blocks neither posting nor another recipient. The webhook's secret and address appear in no log, state, error text or stream. Each of these has a test against a listener the test starts on this Mac.
  • The gate: 135 of the reference's 185 checks pass (was 92), the same on every run, all in the ratchet. The served protocol version is unchanged and equals the reference's. What is left waits on delivery into Claude Code sessions, attachments and room apps.
