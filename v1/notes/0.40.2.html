doz 0.40.2

Fixes for sessions on this Mac (issue #407; step 1 of the session-hub program, #405). Owner 2026-11-16: "i want this work done with a /loop-prep using loop-next ; lets go".

  • swift test works in a fenced --xcode session (dozable issue 40): the test runner (swift-test, and swift-run) and Swift Build's own temporary folders were not among the build tools the fence lets write a temp folder, so the build manifest could not be written. Both swift test --scratch-path "$DOZ_DERIVED" and the default .build now pass.
  • doz sessions restart resumes the right Claude conversation: a session started as claude --session-id ID … comes back with --resume ID (it used to add --continue, which Claude refuses beside --session-id), and a Claude session started without an id resumes the conversation it actually held, not just the folder's newest.
  • A restart whose program dies at once says so: "exited at once (exit N)" with the program's own last lines; doz sessions screen shows that run's last screen, and an ended session keeps its last screen.
  • A foreground doz run @mac returns its program's exit code, also when the program ends before doz attaches (that case used to return 2 whatever the program returned).
  • A Claude login made over ssh is seen: doz also reads ~/.claude/.credentials.json (read-only, never the refresh token) and uses whichever of it and the Keychain's login expires later; doz account ls and doz doctor say where the login came from.
  • New setting mac.fence_loopback_listen (default off): lets a fenced program listen on any port, for test servers that pick one (listen(0)). Off by default because macOS cannot hold such a listener to this Mac alone — a server it starts on all addresses is reachable from your network; --local-port has the same limit, now stated in the manual.
  • Tests: make test 1690 / 0; make test-cli-fence, make test-cli-host, make deckhold-mac-check, make deckhold-verify (the guest holder's bytes unchanged) all pass.
