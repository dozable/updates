BREAKING — a sandbox's or session's files are its "folder"; the daemon's idle timeout (issue #436; chat loop 698, step 1b). The owner: "yes rename the shipped WORKSPACE column and --workdir", "no backward compatibility for the name change ; i want it as a breaking change so --workdir errors and --json field shape changes". The product is about to call the unit (a sandbox, or a session on the Mac) a workspace, so the word stops meaning the files.

  • After upgrading, stop the old daemon once: doz daemon stop. A 0.51 doz and a still-running 0.50 daemon refuse each other with a message that says so (the daemon's protocol version is 3). An always-on daemon with nothing running replaces itself as before; one with sandboxes or sessions running keeps them until it is stopped.
  • Flags (the old ones fail, exit 64, with one line naming the new flag): --workspace DIR → --folder DIR (create, up, try, new, duplicate); --workspace-view → --folder-view; doz run @mac --workdir DIR → --folder DIR; inside a sandbox, doz run NAME --workdir DIR and doz exec NAME --workdir DIR → --cwd DIR.
  • Output: the doz ls column WORKSPACE → FOLDER. --json keys: workspace → folder, workspaceCreated → folderCreated, workspaceRules → folderRules, workspaceView → folderView; a session's workdir → folder (doz sessions @mac --json, doz show --json); the plan of doz up --dry-run --json and doz ignore check|show --json likewise. The dashboard's API: /api/v1/workspace/check|choose → /api/v1/folder/check|choose, fields renamed the same way.
  • Files, with no alias: settings workspace.ignore_mode and workspace.view → folder.ignore_mode and folder.view (an old [workspace] line is no longer read — the default applies — and every command names the new key until it is moved); doz_project.yaml workspace_view → folder_view (the old key is an error); agent-prompt placeholders {{workspace.*}} → {{folder.*}} (the old ones are an error). "Workspace rules" are "Folder rules".
  • Unchanged: /workspace inside a sandbox, --isolated, --ignore-mode, defaults.projects_dir, every environment variable, and the store on disk (a store from 0.50 loads as it is).
  • The daemon's idle timeout: daemon.idle_timeout_minutes defaults to 5 again and sits directly after daemon.always_on in the settings file, doz config show and the Settings page; each says how they combine. It is read only when always-on is off; 0 disables it. A Mac that set only always_on = false now exits after 5 idle minutes. With always-on off and the timeout 0, doz config, the Settings page, doz daemon status and doz doctor warn: "the daemon will not switch off by idling. Once it is stopped it does not come back until the next doz command runs."
