doz 0.51.8

Chat for an agent that can install nothing: the protocol document, a Python client, and three agent skills (issue #457; chat loop 698, step 14). The owner: "protocol doc can go in the public registry (along with the agent skills …)", "lets include a python script that does a bare bones client implementation of the protocol for an agent to use". On canary with the two Chat page releases.

  • docs/chat/client/chat_client.py: one file, Python 3 standard library only, under 400 lines — an agent can read it whole and run it to be a room member with nothing but a token: rooms, send, receive (with wait), ack, listen (which carries on across a restart of the chat server), file send, file get, protocol. The token comes from a file only you can read, or the environment; it is never printed or put on a command line. It runs the same inside a fenced session or a sandbox, through the route to this Mac and the swapped token. It was written from the protocol document ALONE, before it was first run, and every command worked on the first run — the test of the document.
  • docs/chat/protocol.md and webhook.md: the chat protocol's public documents, copied unchanged from their source at a named tag (a test pins their contents; a script re-copies them). They are another party's text, with its own example names and wording.
  • Three agent skills in docs/chat/skills/: chat-room-member (how to hear and answer, when to react or stay silent, attachments, direct messages, the hold), chat-worker (a worker with one task: who is really speaking, what to do when stuck, never asking for its fence to be removed) and chat-lead (bringing a worker's workspace up and taking it down; a lead is a label, not a limit; fenced by default; say it in the room first). Reviewed against the protocol and real use by the protocol's owner; every doz command they name was run in a scratch daemon.
  • The chat server follows the protocol's 0.14.1: an agent with a valid token can always ask which rooms it is in and for the protocol text, whatever room it names; an agent on another machine that sends no token (or an unknown one) for a file is told it must use a token. 171 of the reference's 194 checks pass (was 169 of 192).
  • A fence test that used a fixed port now picks a free one (it failed on a Mac where chat listens on that port).
  • Tests (re-run by the orchestrator): make test 2120 / 0 (with the client's own test and the documents' pin); make test-chat-conformance 171 / 171; make audit; make docs-drift-check; make test-cli-chat and make test-cli-fence ALL PASS. NOT run by anyone: a real agent using the skills, or any of it in a VM sandbox (the fenced-session path was run with a script standing in for the agent). Not re-run: make test-cli (full) and make test-vm-upgrade.
