First run around one base image, ending on a First sandbox (issue #279; loop 627, step 6). Owner 2026-10-20: "v2 (back and next stay where they are) … 3. Should be first sandbox (not a try) ; in fact i think we should drop the special status of a "try" vs not a try but keep the ability to easily delete", then "looks good" on doz-dev.

  • One base, downloaded early. The store has one base (defaults.base, Node.js by default). Onboarding starts its download in the host straight away and carries on asking questions; every tool's image on that base waits for it rather than pulling the same layers again, and that wait shows as its own step, with an hourglass instead of a spinner.
  • The dashboard's setup follows the chosen design: Welcome (this Mac's checks) → Base image → Models & keys → GitHub & SSH → Workspace rules → (official builds: Usage statistics, Stay in touch) → First sandbox. Each title is centred over a column sized to its step. From Models & keys on, a strip at the foot shows the base downloading → preparing → ready (or failed, with Retry), with Details in a popover.
  • Models & keys shows the sign-ins found on this Mac and the keys grouped as Providers / Gateways / No key, each naming the tools it serves; an OpenRouter key works for pi and OpenCode.
  • First sandbox is an ordinary sandbox: pick Claude Code, pi, OpenCode or Codex (those not usable yet are dimmed, saying what they need), a name, a new empty folder or a project folder, and see the same command for Terminal. Quick try now uses the same path.
  • A try is no longer special. Any sandbox that made its own folder removes that folder on doz rm while it is still empty; the try tag and bar are gone. doz try and Quick try stay.
  • doz onboard asks in the same order and ends on the First sandbox; new flags --base, --no-base, --key, --key-name, --first.
  • Tests: full make test 1145, 0 failures (re-run independently); test-cli-onboarding and test-cli-try green twice each (test-cli-try moved off the unpublished Grok Build onto OpenCode 1); the wizard probe green three times (with a key, without secret entry, with the base forced to fail); recipe-check RECIPES=opencode2 on m1b 5/5; make audit and docs-drift-check clean.
