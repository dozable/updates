doz 0.51.15

doz ui publish tailscale: port 80's redirect works on a real Mac (issue #477). 0.51.14 pointed Tailscale's port 80 at a unix socket in the store, which Tailscale serves only for root or a user tailscaled can check with sudo — never true for Dozable's node under its LaunchAgent, so the first real run on m1max set up the node, the name, https and the settings, then stopped at port 80.

  • The redirect now listens on a loopback port (127.0.0.1 only), chosen by publish and recorded with the published address; a re-run keeps it. Port 80 goes to http://127.0.0.1:<that port>, the same kind of target 443 already uses.
  • It still answers only a 308 to the published https address plus the request's path, never a target taken from the request.
  • A Mac published with 0.51.14 is told to run doz ui publish tailscale again (in doz doctor, doz ui publish status and when the dashboard starts).
  • The test suite's fake Tailscale now refuses a unix socket or a path target exactly as the real one does, so this cannot slip through again.
  • Tests (re-run by the orchestrator): the publish and redirect unit suites; make test-cli-alwayson ALL PASS; make audit; make docs-drift-check. The live check (re-publishing on m1max) happens after the release.
