Space files act: doz workspace up -f and down (also doz space up / down).

  • doz workspace up -f FILE brings a workspace up from its space file: it shows the plan first, asks you to confirm

every unfenced agent each time (wherever that setting came from), then makes what is missing — the workspace, its room, its workers — and starts a run. Running it again makes nothing new. Grants a file asks for are recorded as requests for you to grant, never granted by the file.

  • doz workspace down archives the run first, then takes it down: workers ended, their sessions forgotten, rooms and

sandboxes made only for the run removed, scratch folders removed — nothing that holds content goes before its archived copy is checked. What the file keeps between runs (a room, a sandbox's disk, a folder, an agent's memory) stays for the next up, which brings the same room back and lets a persisted agent continue. down --purge retires what was kept too; your own folders are released, never deleted, and nothing external is touched. A file that turns the archive off says so, and down tells you what goes with no copy.

  • A persisted fenced agent's memory is kept by Dozable and given only to its own next fenced session.
  • With a space file, the workspace's brief is the file it names: editing the brief on the dashboard writes that file,

and up never overwrites it. The workspace page shows which space file defines it and whether it is up.

  • doz chat room close / open closes or reopens a room no workspace owns.
