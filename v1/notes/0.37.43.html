doz 0.37.43

Six fixes found by agents driving doz hard (issue #388, Phase 1 of host sessions). Owner 2026-11-12: "fix all the bugs found in the new feature", then "tell deck factory A to ship B7 early to canary" and "yes ship it, then promote to stable".

  • The memory balloon no longer starves a busy sandbox. After a wake, doz used to hand back all but a quarter of a sandbox's memory and keep it, trusting the guest's out-of-memory path to ask for it back; under npm installs and Chromium renders an 8 GiB sandbox ran out of atomic allocations, its OOM killer never ran, and it wedged at 400% CPU for 50 minutes while doz ls hung. Now the guest keeps at least half its memory plus what it uses, nothing is taken back while a session is working, and while the balloon holds anything the host reads the guest's memory every 2 s and gives it all back at once — from its own side — when available memory falls under the reserve, a read is slow, or a session starts working. One stuck sandbox can no longer hang doz ls or doz sessions (it shows as unresponsive after 3 s), and doz down/shutdown on a guest that will not answer stop the VM directly after 30 s.
  • doz starts in about a third of the time: no command checks the 43 built-in recipes at run time any more (the tests do), recipe settings are built only when something reads one, and a recipe catalogue is adopted at first use — doz ls --json 138 → ~48 ms, and 811 → ~320 ms at background priority.
  • doz exec --timeout means it: counted from the moment doz started (a slow or starved start counts), enforced by the host whatever the client is doing; the command is killed, the exit code is 124 and --json says timedOut. A wake or start still under way finishes.
  • Background priority is called out: doz doctor warns when it, or the host, runs at background priority, and a host started by a background-priority command moves itself out of it.
  • Your own --append-system-prompt no longer drops Dozable's environment prompt (#386): the two are combined into one, and a value that already holds the prompt is passed through unchanged. No image rebuild — the launcher is refreshed when a session starts.
  • Tests: new suites for each (recipes checked, lazy settings, exec deadline, priority, launcher, balloon pressure, bounded guest reads), make test 1515 run / 0 failures, make test-vm all pass twice, the new hardening balloon-pressure and test-cli-exectimeout all pass twice, test-cli-startup, the audit and the docs checks. Still to come in the host-sessions feature: doz sessions send / screen, a clear message when a host started over ssh cannot read your Claude login, and sessions on the Mac itself.
