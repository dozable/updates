Feeds and notices. A workspace's room now carries its journal: when an agent records an outcome or a failing review, a notice card appears in the room, "from NAME's journal" (working notes never do; secrets are redacted). Dozable's own notices go to whoever can act: an account that needs signing in again, a host the network keeps refusing, an agent that crashed, a disk running low — to the workspace's manager, or to you when there is no manager (and it says why); a critical one also reaches your Needs you, and when it is about an agent, a fixed one-line notice can be typed into that agent's session, but only while it is idle with nothing typed — never any text from the notice itself. Repeats of the same notice post once in ten minutes, unless it got worse; each feed is rate-limited, never for a critical notice. doz workspace feeds W shows the routes, --dry-run says where a notice would go, --emit sends a test notice, and a space file's x-dozable.feeds changes a route (journal: {to: off} turns the journal card off). A program can post as a feed participant (doz chat add NAME --kind feed), which may post notices and nothing else. Agents see notices in their own list in dozchat receive, only those addressed to them. A notice's shape follows the reference chat server's design; a notice's plain line, for older clients, shows what was written as inert text.
