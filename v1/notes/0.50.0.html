doz 0.50.0

doz host is now doz daemon (issue #411; step 3 of the session-hub program, #405). Owner 2026-11-16: "yes daemon is the name but i dont want aliases for the old 'host' sub command - it should just fail. add a temporary migration code path … easily removable"; the version, 0.50.0, is the owner's.

  • Dozable's background process is the daemon everywhere you read or type it: doz daemon start|stop|restart|status|upgrade-check. doz host … no longer exists — it fails as an unknown command, with no alias. "Host" now means the computer (the coming --host-port and host.dozable.internal).
  • Settings: daemon.idle_timeout_minutes, daemon.screen_capture_minutes, daemon.boot_logs_kept, daemon.keepalive — your existing host.* values are read and moved on the next settings write. The environment variable DOZ_HOST_IDLE is now DOZ_DAEMON_IDLE (the old name is not read).
  • Files in the store: daemon.lock, daemon.sock, daemon.pid, daemon.log (the old log is renamed once). An app that talks to the helper build over its socket uses daemon.sock.
  • --json names: daemon upgrade-check --json → daemonVersion, daemonExecutable; doctor --json check names daemon, daemon priority, daemon login; sessions @mac --json network value waiting (no daemon); the dashboard's actions daemon-start, daemon-restart. Exit code 6 still means the daemon is unavailable.
  • Upgrading is safe: a 0.50.0 daemon takes the old lock as well as the new one, so an older doz can never become a second owner of a store; doz daemon stop stops a 0.40.x process still running; a fenced session keeps running across the hand-over. One temporary migration file does this, to be deleted once every install has run 0.50.0 (backlog 689.B1).
  • No more macOS privacy notices from screenshot scripts: a headless Chrome a script starts is now its own responsible process (Scripts/chrome-launch.mjs), so its touches of its own app are not charged to the app that started it.
  • Tests: make test 1701 / 0; make test-vm-upgrade (0.40.3 → this build, including "never a second owner" and the fenced hand-over), make test-cli-host, make test-cli-fence pass; make test-cli 918 pass with 2 failures that predate this release (backlog 683.B4, 689.B2).
