doz 0.50.5

Start the doz daemon when you log in (issue #425; step 8b of the session access program, #405). The owner approved one per-user login agent as an exception to the old "no launchd agent" rule; the rule this release keeps is that nothing is written without your say.

  • doz daemon login-item on|off|status, and the setting daemon.login_item (ask, on, off; default ask). on writes ONE login item for the store, ~/Library/LaunchAgents/com.dozable.daemon.<8 hex>.plist. It runs a short doz command that starts the daemon the usual way and exits — launchd never runs the daemon itself, and the item has no KeepAlive. It names doz by a stable path, so it runs the current doz after an upgrade.
  • Nothing is written unless you say so. Upgrading writes nothing; the first command in a terminal after the upgrade says once how to turn it on. New installs are asked in onboarding (--start-at-login on|off). The setting is changed on the Mac only — the dashboard shows it and cannot set it.
  • doz daemon stop now holds: while the daemon is always on, it stays stopped until the next doz command or your next login.
  • From ssh (a locked login keychain): a command that needs a daemon starts it in your desktop session through the login item, so it can read the keychain; without a login item, doz daemon restart is refused when it would replace a daemon that can.
  • Shown: doz daemon status (also with no daemon running: --json loginItem, held, alwaysOn, store) and doz doctor's "login item" row — present, loaded, switched off in System Settings, or out of date.
  • Removed by doz daemon login-item off, doz uninstall and doz nuke — only this store's item. Run doz uninstall before brew uninstall.
  • When a future Dozable menu bar app holds the login item, doz removes its own and does not add it again.
  • Known limits: the setting is one for all stores while the item is per store (another store can show "on, not installed"); the doz that runs login-item on is the one the item points to.
  • Tests: make test 1801 / 0; the new make test-cli-daemon (45 rows, a fake launchctl and a scratch agents folder — no test can touch the real ones); make test-vm-upgrade passes, with a check that an upgrade leaves the agents folder empty; make test-cli-keychainlocked, -alwayson, -host, -fence, -onboarding pass (the implementing agent's runs); make test-cli shows only the 2 failures that predate this release. Checked on a real Mac (m1max2) after the canary release.
