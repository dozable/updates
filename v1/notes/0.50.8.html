doz 0.50.8

The menu bar app can start Dozable at login (issue #430; step 9b, the last step of the session access program, #405).

  • One switch in the menu, Start at Login: it starts the doz daemon when you log in, from your desktop session, and brings the menu back too. It uses macOS's own mechanism for apps, so "Dozable" appears under Login Items in System Settings, where it can be switched off; the menu then says it needs approval and opens that page. Nothing is registered until you click.
  • Never two login items: when the app holds it, doz removes its own (doz daemon login-item on's item) and does not add it again; doz daemon status says the menu bar app starts the daemon at login. Turning the switch off, doz app uninstall and doz uninstall take it back.
  • It needs the app in Applications and doz 0.50.8: from anywhere else, or with an older doz, the item is shown disabled with the reason.
  • What starts the daemon is the app's own executable in a small non-window mode: it finds your installed doz, checks it is signed by Dozable, and runs doz daemon start --login-item — the daemon is started the usual way, never as a child of the app. With no doz it does nothing, quietly.
  • Fixed: tests showed a "Dozable is damaged" dialog. The app's test suite built a scratch bundle with a stand-in program inside it, which macOS refused on screen. A test run now never puts a stand-in inside a bundle and never asks macOS to open an app; a run that would is stopped.
  • Fixed: the release's own check of the packed app used a relative path (0.50.7 was released by hand around it).
  • NOT verified by any test — it needs a real registration and a screen: the switch itself, macOS's "Login Item Added" notice, the System Settings row, the daemon and the menu coming back after a restart of the Mac. Checked on the test Mac after this release.
  • Tests: make test 1904 / 0; make test-cli-app and make test-cli-daemon pass, with a recording stand-in for macOS's login-item service; the release script's local run of both flavours; make test-updates 60 / 0. make test-cli shows only the 2 failures that predate this release.
