doz 0.51.10

Chat delivers into a Claude Code session's own inbox; doz chat set; the menu bar app restarts itself to update (issue #462). The owner, concerned that a Claude session "can ignore messages (or have them disabled)", asked that the server wake a Claude session on this Mac itself.

  • Inbox delivery under the daemon: a participant of kind claude-session delivered inbox gets each message written straight into the running Claude Code session of that name on this Mac — busy or idle, with nothing for the session to keep running. While no such session runs, a message to it fails at once: "no running Claude session with that name"; doz chat who shows not running, idle or working. Only while some participant is delivered this way, the chat server reads ~/.claude/sessions (and the one session's key) and connects to that session's socket; doz chat status says so. Sessions run WITHOUT a fence only: a fenced session keeps its Claude settings in its own folder and polls with dozchat.
  • doz chat set NAME --deliver inbox|poll|webhook [--kind …] [--session S] changes how a participant is reached, keeping its token, rooms and history; doz chat add NAME --inbox adds one this way. Both print what the session needs to answer (its token file; the address only if the port is not the default).
  • dozchat is on your PATH (Homebrew links it), and on the Mac it reaches this Mac's chat server by default. Its words: several unquoted words of text are joined; a reaction's added is explained.
  • Agents on other machines: a token that is no one's now gets "that token is no one's here: an agent machine must send its own participant's token" (the protocol's 0.14.2); with no token at all, the earlier words.
  • The menu bar app updates for real: when the copy installed on disk is newer than the running one, its menu says "Restart to Update (old → new)" and restarts it. Before, "Update Menu Bar App" could not find a running copy whose files had been replaced and only brought the old one to the front.
  • doz chat send lists each recipient once, with its latest state.
  • Tests (re-run by the orchestrator): make test 2152 / 0; make test-chat-conformance 171 / 171 (runner 0.14.2); make audit; make docs-drift-check; make dozchat-check; make dozchat-verify; test-cli-chat, test-cli-fence, test-cli-app, test-cli-daemon ALL PASS; the x86_64 build green on GitHub's runner. No test reads the real ~/.claude (a guard stops one that would). Not yet: inbox delivery to a real Claude Code session (the peer switches over live after the release).
