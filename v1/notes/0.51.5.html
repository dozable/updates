doz 0.51.5

Chat: webhook bots, agents on other machines, and import (issues #448 and #449; chat loop 698; the owner's overnight goal: "i want to wake up with Cheto chatting with you running latest dozable stable"). The doz chat group is still hidden from doz --help; doz chat --help lists it.

  • Webhook bots. doz chat add NAME --kind grok-bot --webhook, then doz chat webhook set NAME reading two lines — the address, then the Authorization value — from standard input or a file only you can read; webhook status (the host and a fingerprint, never the path or the value) and webhook remove. The entry is kept in your login keychain and handed to the chat server through a pipe when it starts: never in a file, a log, a status or a command line, and only you on this Mac can set it (not the dashboard, not another device). Addresses: https to any host, its certificate checked; plain http only to this Mac or a Tailscale address. No redirect is followed and no proxy is used. Messages still waiting for a bot go to its new address when the entry changes, and fail at once when it is removed.
  • Agents on other machines. Two settings, set on this Mac only: chat.remote_listen (this Mac's own Tailscale address) and chat.remote_agents (the exact addresses of the machines that may connect; no ranges). Both chat ports then also listen there. Every caller from another machine is an agent: it must be in the list and present its own token; it gets the agents' calls and files with its token, never your page, and can never act as you — a line that claims to be from you under an agent's token is recorded as that agent. Nothing listens beyond this Mac until both are set, and never on a local-network or "all" address. doz chat status, doz daemon status and doz doctor say so while it is on.
  • Import. doz chat import COPY [--dry-run] [--add-missing] [--replace] brings in another chat server's history from a copy made for import: rooms, messages, attachments, holds, avatars. A dry run prints what would come in and the commands to add anyone missing. Every file is treated as untrusted (a copy holding secrets, a link, or a room file with anything unexpected in it is refused with nothing written); nobody is renamed; nobody is woken (what was still waiting is marked cancelled, not delivered again); chat must be off; history already here is never merged or overwritten — with --replace it is kept aside.
  • Participants have a kind (agent, claude-session, grok-bot); doz chat who shows how each is reached and the server's own word for its presence.
  • The conformance pin is the reference's 0.13.2: 169 of its 192 checks pass (every one but attaching a file by its path, left out on purpose; room apps are not in the port). An agent may fetch a file with its own token, also from this Mac; part of a file may be asked for.
  • Fixed, from 0.51.4: an answer larger than the socket's buffer was cut short about one time in six (doz chat read of a long room failed; a large answer to an agent could be cut the same way) — the connection now closes only after the answer has reached the socket. The chat server creates every file readable by you alone.
