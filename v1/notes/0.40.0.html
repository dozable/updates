doz 0.40.0

Sessions on this Mac are fenced by default (issue #398). Owner 2026-11-12: "default fenced with opt out with --unfenced", the Keychain "blocked by default with flag to allow", and a setup wizard for the common cases; shipped as 0.40.0 on the owner's word.

  • A fenced session (doz run @mac, now the default) runs inside macOS's own sandbox (Seatbelt): it reads and writes only its project folder and its own temporary files, caches and agent settings; it reads your tools but not your secrets or other folders; your Keychain is closed (--keychain opens it); git hooks and config are guarded (a session that adds a dangerous key is stopped and can be resumed). --unfenced (or mac.fence off) gives a session exactly what it had before. Sessions opened before keep their mode across restarts.
  • Its network goes only through its own Dozable proxy, with the same permissions a sandbox has (--permissions, doz net … @mac --session S, every connection logged); DNS, UDP and direct connections are closed, and it never reaches this Mac's own addresses. --local-port for a dev server.
  • Claude Code in a fenced session gets its own settings folder by default (your instructions and skills read-only, a cleaned copy of your settings; --agent-config shared uses your own ~/.claude), its login through the proxy (it never holds your token), and its conversations carried back to ~/.claude/projects/<folder> when it ends, archived under the history setting (--transcripts).
  • Tools: git and ssh through the proxy (doz fence-connect), GitHub as you (--github read|push, the token never enters), your SSH agent (--ssh-agent, list and sign only), worktrees, submodules and LFS, Node/Python/Go/Rust/Swift package registries, --xcode and --simulator (the Simulator a guard rail, not a boundary). Open URL, open files and the clipboard work, each announced, and can be switched off live.
  • What a session can do is shown as named states: doz sessions @mac --capabilities NAME, doz run @mac … --dry-run, and the dashboard's This Mac page — chips on each tile, a "What it can do" tab with the live switches, Network and Conversations tabs, a Watching | Controlling toggle, and New session on this Mac…, a wizard for five setups (plain agent; web/Node; Swift/Xcode; signing and notarisation, unfenced; unfenced) that gives the exact command and never starts one itself.
  • Scripts that need the old behaviour — calling doz from inside the session, using your Keychain, reaching any host, running from your home folder — should pass --unfenced (older versions do not know the flag: check doz run --help).
  • Sandboxes too: a sandbox can no longer reach this Mac through any of its addresses (Wi-Fi/Ethernet, VPN or Tailscale), link-local addresses or the cloud metadata address, whatever its permissions — mac.dozable.internal:PORT still reaches a model server on the Mac. "Use GitHub" now includes GitHub's Git LFS file host.
  • The manual's chapter on sessions on this Mac is rewritten fenced-first, including what the fence is not. The lists of system services the agent and Xcode profiles may use are provisional.
  • Tests: make test 1681 / 0; make test-cli-fence (366 checks with the real-internet rows), test-cli-host, test-cli-github, test-vm-network all pass; test-vm-claude (4) and test-cli-permissions (1) fail exactly as on the previous release.
