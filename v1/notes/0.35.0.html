doz 0.35.0

OpenCode 2, a choice of major version, and a model source and model for every tool that can take one (issue #259; owner 2026-10-17: "Ok great. /ship"). Canary: stable moves on the owner's promote.

  • OpenCode 2 has its own recipe (@opencode/cli 2.0.29) and is the recommended opencode. OpenCode 1 keeps its recipe and is updated within 1.x only.
  • An earlier major, everywhere a tool is chosen:
  • opencode@1 selects OpenCode 1, and opencode@2.0.29 selects an exact release;
  • it works in doz try/new/create/up, doz_project.yaml (agent: opencode@1), doz search and the doz try list;
  • Quick try shows one OpenCode card with a Version choice;
  • New Sandbox's agent picker offers both majors.
  • An existing sandbox never changes major.
  • Gateways for every OpenAI-compatible tool: OpenRouter and Vercel AI Gateway are offered to 22 more recipes, set by env, the tool's own config file, launch arguments or a settings file written on each run. Recipes that aren't offered a gateway say why: Grok Build, Claude Code, Codex, Antigravity, ADK, Gemini CLI and Stitch. CodeWhale and Maki take OpenRouter only.
  • Choosing a model: the host fetches each gateway's public model list on the Mac and caches it for 24 h.
  • The Try setup and New Sandbox have one "Where TOOL gets its model" section: providers, then gateways, each with its key in its row. A searchable model picker follows, and typed ids are still allowed.
  • In the CLI: doz models, plus a did-you-mean for --model.
  • doz_project.yaml takes model_source: and model:.
  • OpenCode Zen's free models, with no key: a model source of OpenCode 2 (doz try opencode --provider opencode-zen).
  • There's no account, and no key enters the sandbox; an account added later is used instead.
  • The network allows only Zen's two inference paths on opencode.ai, not its Console sign-in.
  • Eight free models, each with its data terms shown in the picker and in doz models.
  • The Guide says a key added with OpenCode's own /connect is stored inside the sandbox.
  • Fix: adding the first gateway key in the Try setup kept asking for a key, even though the model picker had already loaded with the new key.
  • Fix: the web Try now plans the pinned version, as the CLI does. A host that couldn't reach the registry used to refuse.
  • Blog and newsletter: a tool-news topic of its own (Worker deployed on the owner's go).
  • Fix (recipe-check): the leak check counted the agent's own background calls to its chosen source (pi listing OpenRouter's models), which failed pi · openrouter in every full run; it now counts only requests to the host it tested, and a failure names them.
  • Tests: make test 1114 tests, 0 failures, 4 skipped. make recipe-check RECIPES=all covers 205 recipe × source checks: about 55 min on m1b, and 39 min on the M4 from a warm store. The model-source browser probe passed on a fresh store at 1440 and 390 px, light and dark. No real call to OpenCode Zen was made.
