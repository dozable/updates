doz 0.50.2

Reach a service on this Mac: --host-port and host.dozable.internal (issue #417; step 5 of the session access program, #405). A sandbox or a fenced session could not reach a server running on the same Mac — every address of this Mac is refused, by design — except the one model-server port a sandbox was made with.

  • --host-port PORT (repeatable, up to 16) on doz create, doz up, doz run and doz run @mac; host_ports: in doz_project.yaml. Inside, the service is host.dozable.internal:PORT; mac.dozable.internal is the same route, and a sandbox's model-server port is one entry of the same list. The proxy connects to 127.0.0.1:PORT and nothing else of this Mac: the same port by address (127.0.0.1, localhost, the Mac's LAN or Tailscale address) is still refused.
  • The permission host:PORT: doz net allow|deny NAME host:PORT (and @mac --session S) changes it live; also a word in --permissions / --allow. The setting network.host_ports_live (on by default) — off: ports are fixed at start; taking one away always works. Open does not include it: Open opens the internet, not this Mac.
  • Never opened: Dozable's own ports (the dashboard, a proxy, a sandbox's forwarded web port — checked when granted and at each connection), port 0 and ports below 1024.
  • PORT:tag names the sandbox (NAME) or session (@mac/NAME) to the service in an X-Dozable-Session header on plain-HTTP requests, replacing any copy the program sent. It identifies; it does not authenticate. A CONNECT tunnel is never read.
  • Shown in doz net show (--json hostPorts), the agent's facts, a fenced session's capabilities, the plan and the dashboard (read-only). --unfenced --host-port is refused: an unfenced session already reaches every port.
  • Help: doz help run, create/up --allow and doz net permissions now list site:HOST[:PORT] and host:PORT.
  • Limits to know: doz up on an existing sandbox does not apply new host_ports: (use doz net allow); a live grant reaches the agent's facts at its next session.
  • Tests: make test 1735 / 0; make test-cli-fence passes with the new rows (the route by both names, plain and CONNECT; every address form still refused; live allow and deny; the setting off; the tag; the record across a daemon stop); make test-vm-network passes with a sandbox reaching the port by name (it sets the proxy's list directly — doz create --host-port through the daemon has no VM test; the fence rows cover that path for sessions). make test-cli-host is the implementing agent's run.
