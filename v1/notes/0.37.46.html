This Mac in the dashboard (issue #395). Owner 2026-11-12: "go, start the dashboard feature", then "ship to canary and install on m1max so i can try it".

  • A "This Mac" page in doz ui (and its sidebar entry, marked "no isolation") shows the sessions running on this Mac (@mac): a tile per session with its live picture, its folder, a permanent No isolation label and, for a session whose own command asked for it, permissions bypassed. A callout says what that means: they run as you — your files, Keychain and network — with no sandbox and no proxy.
  • Watch first: opening a session shows it read-only ("watching — what you type does not reach it"); Type into it switches to typing. Restart… and End… ask before they act. New sessions are started from a terminal (doz run @mac), never from the page.
  • All sessions ends with a This Mac section linking to the page.
  • Your other devices see none of it by default: doz ui --lan / doz serve refuse host sessions unless the new setting serve.mac_sessions allows them — watch (list and watch) or interactive (also type, end, restart); default off, set in the settings file or by a flag, never from the page. A sandbox can never reach these routes.
  • A sandbox that stopped answering is shown as "not answering" in All sandboxes, with a callout on its page.
  • doz sessions restart no longer ends a Claude Code session that never had a turn: it continues the conversation (--continue) only when the folder has one, and otherwise starts fresh and says so.
  • Tests: make test-cli-host (with a fake claude for the restart cases), new web suites (routes, tickets, the exposure classes, actions, the unresponsive sandbox), make test 1572 / 0, css-lint, the audit and the docs checks; screenshots of the page in a headless Chrome on a scratch store.
