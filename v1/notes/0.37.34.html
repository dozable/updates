Settings per recipe (issue #360; loop 627, step 20 — the design is 659's). Owner 2026-10-30: "ship 659 with 669".

  • A recipe's settings are its own: every recipe's settings are generated as [recipes.VENDOR.PRODUCT] (version, approvals, memory_mib, network, plus what a recipe declares, such as Codex's keep_alive). The old names (images.claude_code_version, claude.permissions, [images.<agent>]) are still read, and the first write moves them, keeping a one-off doz.toml.0.37.bak. A file that does not parse is never touched. A fresh doz config init lists 65 settings.
  • One precedence for everything: flag › env › sandbox › project › Mac › default (a recipe's own, or Dozable's), and every value says where it came from. --approvals skip|ask on new, create, up and try, approvals: in doz_project.yaml, doz config set --sandbox NAME; a sandbox records the values it was made with.
  • doz config: show prints Dozable's own settings and "Recipes in use … · installed …"; --agent, --sandbox, --project DIR and --all; set/unset say which place they wrote.
  • Recipes by state: doz recipe ls has a STATE column (available, installed, in use) and --installed; doz recipe uninstall ID removes a recipe's baked images, refused while a sandbox runs it, keeping its settings unless --forget-settings.
  • The subject: a recipe may name what its agent is (pi: "coding harness", Fabric: "agentic tool"); otherwise "agent". It sits where an older doz already reads it, so older versions still take the catalogue.
  • The dashboard: a Recipes group in the sidebar — Installed (in use and installed, each recipe's page with its settings, baked images, sandboxes and Uninstall), Browse (the whole catalogue, searched) and Quick try. Settings is laid out like VS Code's: a search across the top, the sections on the left when the page is wide enough, each setting a block with its control under it and the ones you changed marked. defaults.permissions is a matrix of Locked · Standard · Open with Custom for the checklist, and its switches are now only the shared ones (they used to list every recipe's own). A sandbox's Config tab shows its own values beside the Mac's, with Follow the Mac.
  • The style guide has every setting control in one section ("Setting controls — every pattern"); the manual uses the decided words and 15-settings-reference.md is generated per recipe.
  • Tests: the full suite (1407, 0 failed); the dashboard's 299 after the later changes; make audit; make docs-drift-check; headless-Chrome probes for Recipes, Browse, Settings and the matrix (1440, 900 and 390 px, light and dark). make test-cli was not run (it needs the VM host).
