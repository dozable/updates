doz 0.52.55

The fixes from the third-party user tests and the cold read of the manual. A refused website now says so inside the sandbox: an HTTPS request to a host the policy refuses is answered with "refused by Dozable's network policy, not a network failure", naming the doz net command that shows it and the one that allows it (nothing is contacted; a program that ignores the proxy still sees a lookup failure). The remotion-video preset allows remotion.media, and doz workspace new --site HOST allows a site for every agent the workspace starts. doz exec past its timeout says so and how to give it longer, and the sandbox reaps orphaned processes, so none are left behind. A usage error with --json answers in JSON (exit 64). doz onboard --claude-account none declines the Mac's Claude login without a prompt. A lesson decided with doz workspace decide reads "applied" or "declined", never "withdrawn"; doz resources no longer lists the daemon's hold marker as a stray; and daemon status and doctor say when the menu bar app starts another store's daemon. The manual's description is corrected (your keys never go inside a micro VM or a fenced place; agents run as you only when you choose that), it names only published agents, it compares where agents run in one table, its worked process example runs in an order that works, and each version's site redirects the old onboarding page.
