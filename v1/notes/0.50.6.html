doz 0.50.6

Keep this Mac's Claude login renewed: doz account keepalive always (issue #418; step 8c of the session access program, #405). On an unattended Mac that runs only fenced sessions, the Mac's Claude login lapsed and no new session could start until someone opened Claude Code on its screen.

  • doz account keepalive off|on|always. always: while the daemon runs, it renews the Mac's Claude login when it expires, with no sandbox needed. on (as before) only while something used the login in the last 15 minutes — and a fenced session on this Mac now counts.
  • It runs when the login expires, not before — a fix to the keep-alive that already shipped. Measured on a real Mac (Claude Code 2.1.325): the keep-alive's command run 8 minutes before expiry renews nothing. The old rule ran once, up to 10 minutes early, and never again for that expiry. Now the first run is at the expiry; a run that renews nothing or fails is tried again 1, 5 and 15 minutes later, then every 30 minutes, six runs at most.
  • What it is: Dozable runs this Mac's own Claude Code once, with a fixed command, no tools, an empty folder and a scrubbed environment. Dozable still never holds or writes Claude Code's refresh token.
  • What stops it, and it says so: a daemon started where the login keychain is locked (over ssh); Claude Code not installed; an unfenced Claude Code running on this Mac — named by its process and session (it holds its own copy of the login, and renewing under it is not proved safe). Claude Code's own background process counts as one. A fenced session does not stop it.
  • Shown in doz account ls (--json keepalive), doz daemon status and doz doctor: the mode, the last renewal, the next try, a failure with its reason — never a token.
  • A login that exists only in Claude Code's credentials file (signed in over ssh) is now read as expired when it expires, not as signed out, so it can be renewed.
  • Asked once, on a terminal, after the "start at login" question and after doz daemon login-item on.
  • Not settled, stated plainly: whether a renewal by another process cancels the login a running interactive Claude Code holds. On the test Mac an idle interactive session with Remote Control renewed the login itself within minutes of expiry.
  • Tests: make test 1823 / 0 (the timing, the retries, the skips, the record); make test-cli-host, make test-cli-fence, make test-cli-keychainlocked pass with new rows; a real race (two looks both starting a run) found and fixed. Every test run uses a fake Claude Code; the real one is never run by a test. make test-cli was not re-run on the final code (before the timing change it showed only the 2 failures that predate this release). No VM test.
