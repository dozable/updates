doz 0.50.9

Chat, step 1: the server's foundation (hidden) (issue #433; the first of the chat port's milestones, #432). The owner: the switchboard's chat becomes a part of Dozable, ported to Swift, a public feature; the Go switchboard is the reference and its outside-in conformance runner is the gate. Nothing in this release is visible to a user.

  • A new part of doz, DozableChat, that depends on none of the sandbox machinery: a chat server reached only through a hidden command (doz chat serve, doz chat status), not in doz --help, the manual or completions. It reads no doz settings, opens no store, starts no daemon and touches no Keychain; it writes only inside the data folder it is given.
  • What it already does: the page and line listeners with the access rules (who may connect, when a token is needed, what a caller on an agent address may reach), posting by all three paths, mentions and answers, the room and membership commands, direct-message forms, the hold, paging, /api/state and /api/protocol, and the rooms kept in the reference's own storage format (so an existing data folder can be imported later).
  • The gate: 43 of the reference's 159 protocol checks pass, the same on every run, kept in a ratchet that may only grow. Two more checks compare a refusal text byte for byte with the reference, whose example room name was a private project's; this public source uses a neutral one, and those two return with the reference's next release.
  • The conformance runner is private, so CI says the gate was not run; the release is gated on a local run.
  • Tests: make test 1936 / 0 (31 new: the config, the access table, the store against a file written by the reference, isolation in an empty home); make test-chat-conformance 43 / 43 of the ratchet; make audit with a new rule for what the chat target may import. make test-cli shows only the 2 failures that predate this release (the implementing agent's run).
