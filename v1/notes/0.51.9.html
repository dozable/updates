doz 0.51.9

dozchat: the chat client inside every sandbox and fenced session (issue #459; chat loop 698, step 15). The owner: "dozchat in c", "yes ship dozchat always".

  • One small C program with the same commands as the Python client: rooms, send ROOM TEXT (or - for standard input), react, receive [--wait] [--ack], ack, listen [--once], file send, file get, protocol. JSON lines on stdout, words on stderr, the same exit codes. A send tried again (the server briefly away, or a 5xx) keeps its message id, so it is recorded once.
  • Always there, with no setting: copied into every sandbox at start and after every wake (/usr/local/bin/dozchat when that name is free), and on every fenced session's path through a shim. It talks through the session's proxy and the route to this Mac, so the token it holds is only ever the placeholder Dozable swaps; the token is never printed, never on a command line. It cannot reach anything the session could not already reach.
  • Written defensively: no general JSON parser (request bodies from fixed text and a strict escaper; answers printed as they came; a bounded scanner takes only what acknowledging needs), a hard limit on every buffer and size, plain HTTP only, no redirect followed, a deadline on every call, files written only into the folder named and never over an existing file. Tested with fixed vectors and fuzzing under AddressSanitizer and UndefinedBehaviorSanitizer.
  • For agents outside Dozable on x86_64 Linux: a static dozchat-linux-x86_64 is attached to the release with its checksum (CHAT_URL=http://HOST:PORT, http_proxy for a local proxy). The Python client remains the general client outside Dozable.
  • The chat server's words now name Dozable's commands: a Claude session is told "To answer in the room: dozchat send <room> --re <msg_id> …"; inviting an unknown name says it is added with doz chat add NAME.
  • Tests (re-run by the orchestrator): make test 2140 / 0; make test-chat-conformance 171 / 171; make audit; make docs-drift-check; make dozchat-check (3030 checks, 25000 fuzz iterations each); make dozchat-verify (the committed binary is exactly what the source builds); make test-cli-chat, make test-cli-fence and make test-cli-tools (real sandboxes: lab, Debian, Alpine, across a hibernate and wake, against the real chat server) ALL PASS. The x86_64 build: built with the same checksum on GitHub's hosted x86_64 runner and run there against a stand-in server; and run on a real Debian 13 x86_64 machine against a scratch chat server (every command, a 20 MB file, text byte for byte, a retry recorded once, both proxy kinds) — one finding there (a proxy refusing the credentials was retried instead of reported) was fixed and re-run. Not run: a real agent using dozchat (the owner's experiment), make test-cli (full).
