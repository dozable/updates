doz 0.37.30

tmux 3.8 in every sandbox (issue #238; loop 627, step 26). Owner 2026-10-26: "go".

  • No base ships 3.8: the probe read every catalogue base's package index. Debian 12 and the images built on it have 3.3a, Ubuntu 24.04 and Alpine 3.20 have 3.4, and eclipse-temurin's Ubuntu 26.04 has 3.6a. Only Debian sid and Alpine edge have 3.8.
  • Dozable's own tmux: one static aarch64 binary (tmux 3.8, libevent 2.1.13, ncurses 6.6, musl), built with the pinned Zig 0.16.0 from sha256-pinned tarballs by Guest/tmux/build.sh. Three builds gave identical bytes, and make tmux-verify rebuilds it and checks the committed bytes. It is listed in PROVENANCE.md, LICENCES/ and the release's third-party notices.
  • Copied in, never downloaded: with sessions.tmux on, the tools layer copies it to /usr/local/lib/doz/bin/tmux, but only when its sha256 matches the pin. It is linked as /usr/local/bin/tmux when that name is free. The distro's tmux is never touched. It is kept when the setting is turned off, because only a client of the same version can end a running server.
  • Sessions: a new session runs in Dozable's tmux. A session already running in the distro's older tmux keeps it, and ending a session tries both. The tmux conf did not need any version-specific lines.
  • Limits, now in the manual: OSC 7501 (agent status) does not get through tmux 3.8 unless it is wrapped, and Claude Code sends it unwrapped, so allow-passthrough stays off. The "no tmux" message now points to doz tools NAME --apply. No image or bake key moved.
  • Tests: the full suite (1367, 0 failed); ToolsLayerTests; make test-cli-tools (46 checks); make test-cli-tmux38 passed on Debian and Alpine (75 checks: the server version, copy by OSC 52 and xclip, xdg-open, the light/dark theme reaching a pane, and an older-tmux session kept).
