Dozer Sandbox is now Dozable: the name people see, everywhere in the app (issue #271; owner 2026-10-18: "do as much as you can … Yes make public"; trademark search on Dozable and Dosable clear). Canary: stable moves on the owner's promote.

  • The name: doz --help, setup, uninstall, init, every message, the dashboard (title, install name, every view), the agent prompt, recipe and schema prose, README, CONTRIBUTING, the 29-chapter manual, the CLI guides and DocC say Dozable. doz stays, "the Dozable command line".
  • Kept on purpose, because shipped builds read them: the update feed updates.dozersandbox.com/v1/feed.json and its signed message, the tap dozer-sandbox/tap and repository constants (they move with the GitHub org, later), the store and config folders (dozer-sandbox), Keychain doz-* names, the recipe namespace com.dozersandbox/*, /run/dozer* and .dozer* in the guest, and the Swift target names.
  • The default projects folder for new installs is ~/doz-workspaces (owner 2026-10-18). A Mac that already has ~/dozer-sandbox-workspaces keeps using it while defaults.projects_dir is unset; an explicit setting always wins (Workspace.unsetProjectsDir).
  • Left for a guest-image rebuild: the text inside guest-injected scripts (clipboard shim version line, "no terminal of a Dozer session"). Also unchanged: User-Agent: Dozer-Sandbox, LICENSE/NOTICE, profiles/*.json (regenerated only by VM runs).
