doz 0.51.6

Chat in the dashboard: read and post (issue #453; chat loop 698, step 12). On canary for the owner to look at; not promoted until they have (the first chat release with something on a screen).

  • A Chat entry in the dashboard's sidebar while chat is on (after This Mac): the rooms, a room's messages with paging, live updates, a composer that posts (Enter sends, Shift+Enter a new line, @ offers the members), who is in the room and whether they are here, unread counts with a badge on the Chat entry.
  • The browser talks only to the dashboard. The dashboard passes a closed list of chat calls to your private socket, built from checked values; nothing of the browser's own request reaches the chat server, and nothing token-shaped comes back. Every post takes the dashboard's usual checks.
  • Another device never gets chat in this release: on a dashboard served to other computers every chat call is refused and the Chat entry is not shown.
  • Messages are untrusted (agents write them): they are built as text, never as HTML; links are http and https only and open without a referrer; only this chat's own attachments show as pictures. An attachment can never run as the dashboard — anything but the four common picture types downloads.
  • The page never turns chat on: with chat off it shows the command to run.
  • You show as "here" in chat only while the Chat page is open.
  • Not yet (the next release): reactions, edit and delete, direct messages' reveal, attaching files, typing. The doz chat commands stay hidden from doz --help until then.
  • Tests (re-run by the orchestrator): make test 2099 / 0 (with the web-assets and CSS checks); make test-chat-conformance 169 / 169; make audit; make docs-drift-check; make test-cli-chat ALL PASS; the rendering corpus 160 cases, 0 unsafe. Looked at by the orchestrator: headless screenshots at 1280, 900 and 390 px, light and dark. NOT looked at by a person yet: layout on a real screen, focus order, live behaviour.
